# Zara Try-On Cloudflare Worker

This is an **integration adapter, not an image generation model**. GitHub Pages stays the web frontend. Its Avatar Studio sends the chosen avatar and dress as base64 images to this Worker.

## Deployment
1. First confirm the exact name of the existing Worker in Cloudflare. The screenshot suggested an autogenerated name with `muddy-bread`; do not create or overwrite another Worker unintentionally.
2. In that Worker's **Settings > Builds** connect GitHub repository `manzoor4670/zara-ai-companion-` on branch `main` if not already connected. Account-level GitHub connection alone is insufficient.
3. Use this file as the Worker entry point with your chosen build method. If using Wrangler, configure `main = "worker/src/index.js"` and **name = the exact existing Worker name**, then deploy using `npx wrangler deploy`.
4. Add `TRYON_PROVIDER_URL` as Cloudflare environment variable or secret and `TRYON_PROVIDER_TOKEN` as a secret if provider requires a token. The provider must accept POST JSON `{avatar,dress,instructions}` and return JSON `{image:"data:image/png;base64,..."}` or an HTTPS image URL. Choose an authorized image try-on provider; no provider is bundled.
5. After deployment, paste the exact HTTPS Worker URL in Zara Avatar Studio's **Secure try-on endpoint** field.

## Status
GET / responds with service and `ready:false` when not configured. POST responds with 503 until the provider is configured. **No actual dress generation is available yet.**

## Security
Never commit tokens to GitHub or enter them in public GitHub Pages. This is a development prototype and its browser origin check is not full authentication or abuse prevention. Before public use implement server-side authentication, request quotas/rate limiting, and consent checks. Uploaded photos are sent to the selected provider when Generate Try-On is clicked.
